## 一、选玩法的三条硬门槛（先筛掉不合适的）

个人主体 + 零成本 + 多端分发，玩法必须同时满足：

1. **无后端**：纯单机 / 本地存档，不买服务器、不做域名 ICP 备案（备案只做小程序备案，免费）
2. **零外购素材**：只用几何图形 + 纯色 + 系统字体。买素材既费钱又会卡审核（版权证明拿不出来）
3. **无版号风险**：不碰棋牌、捕鱼、抽奖概率、他人 IP —— 这几类个人主体在微信**直接上不了**

**另外一条现实约束**：平台推荐算法看的是**留存**和**持续更新**。所以玩法要能在**不手工设计关卡**的前提下持续产出内容，否则做不长。

## 四、推荐：候选 A（车位脱困）

**推荐理由（按重要性排序）**

1. **需求被榜单直接验证**，而且是在**个人可做的品类**里验证的 —— 不是棋牌那种我们进不去的赛道
2. **关卡可以程序化生成 + 自动验解**（生成后跑一遍求解器，保证有解才投放）
   → 这是三个候选里唯一能做到"**不手工做关卡也能持续更新**"的方向。
   平台推荐算法看重"持续更新"，这一点决定了能不能做长线
3. **100% 几何渲染**：没有一张要买的图，审核不需要版权证明，包体积还小
4. **广告位天然合理**：提示 / 重排 / 跳过，都是玩家主动要的，不会因为广告伤留存
5. **难度可量化**（车辆数、步数上限、障碍比例都是数字）→ 方便做"留存导向"的难度曲线，这是算法喜欢的
6. **单局 20~60 秒、可随时中断**，天然适合小程序"点开即玩"的形态

**B 和 C 为什么不作为首选**

- B（数字合并）开发最快，但**同质化是所有品类里最严重的**，且没有关卡生成的空间 —— 拼的是美术和差异点，我们零素材等于放弃优势
- C（分类整理）正在风口上，但**关卡要手工设计**，做一批就枯竭，留存会掉，而我们不做内容引流，撑不住更新

**如果 A 做出来数据不行**，B 是最理想的备选（改动量小，一天能切换验证）。
