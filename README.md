# mini-game-multiplatform

一套代码，多端小游戏。当前玩法：**车位脱困**（6×6 停车场，拖车腾路，把红车从出口开走）。

## 为什么是这套方案

| 约束 | 本方案 |
|---|---|
| 预算 ≤ 200 元 | 零依赖、零引擎、零构建工具链，成本 0 |
| 无企业资质 | 只走个人主体可用的广告变现（IAA） |
| 要覆盖多平台 | 一份 `src/` 同时装配出 Web / 微信小游戏 / 抖音小游戏 |
| 微信主包上限 4MB | 实测主包约 40 KB（余量 99%） |

**不用游戏引擎的理由**：引擎自带运行时会先吃掉主包额度（4MB 上限），并引入几百 MB 的工具链；
超休闲玩法的复杂度用原生 Canvas 完全够。

## 目录结构

```
src/
  config.js                  全局配置（广告位 ID 填这里）
  main.js                    启动装配（三端共用入口）
  data/levels.js             关卡表（由 tools/genlevels.mjs 离线生成，勿手工改）
  core/
    rush.js                  玩法引擎：棋盘模型 + BFS 求解器 + 关卡生成器（零渲染）
    game.js                  游戏层：渲染、拖拽交互、关卡推进（零平台 API）
    adapter/
      index.js               适配层入口 + 平台探测
      minigame.js            微信/抖音通用适配器工厂
      wx.js / tt.js          两个薄壳
      web.js                 浏览器适配器（含模拟广告，开发期能跑通链路）
tools/
  build.mjs                  三端构建（输出 dist/ 并报告包体积）
  smoke.mjs                  冒烟测试（假 DOM 在 Node 里真跑逻辑）
  genlevels.mjs              关卡表离线生成器
dist_tpl/index.html          Web 端页面模板
requirements/                需求与方案文档（每版本一份）
```

**架构铁律**：
1. `core/game.js` 与 `core/rush.js` **不允许出现** `wx` / `tt` / `document` / `window`，平台能力一律走 `adapter`
2. **核心玩法与关卡生成器必须零渲染零依赖** —— 这样它们能直接跑在 Node 里被自动化测试覆盖

## 命令

```bash
# 三端构建（输出 dist/web、dist/wx、dist/tt，并打印体积）
node tools/build.mjs

# 冒烟测试（玩法引擎 + 游戏层，含架构纯净性检查）
node tools/smoke.mjs

# 重新生成关卡表（改难度或加密度时用；BFS 约 0.6s/关，200 关约 2 分钟）
node tools/genlevels.mjs 200

# 本地预览
python -m http.server 8707 --directory dist/web
# 浏览器打开 http://127.0.0.1:8707
```

## 本地开发环境

**只需要一个工具：微信开发者工具**（不用 Cocos 之类的游戏引擎）。

1. 下载稳定版（Windows 64）：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
   当前稳定版 `2.02.2608070`（2026-09-07），约 182 MB
2. 双击安装包 → 一路下一步 → 启动后**微信扫码登录**
3. 工具首页点「**+**」→ 选「**导入项目**」
4. **目录**选 `dist/wx`（**不是**项目根目录，也**不要再往下点进 `src`**）
   ⚠️ 选错会报 `Error: game.js: 未找到 game.js 文件` —— 那就说明目录多进了一层，
   正确目录里应该能直接看到 `game.js` / `game.json` / `project.config.json` 三个文件
5. **AppID** 选「测试号」即可先进模拟器试玩（还没注册小游戏账号时用这个）
   ⚠️ 项目类型必须是**小游戏** —— 工具会读 `project.config.json` 的 `compileType: game` 自动识别，
   若让你手选，选「小游戏」
6. 左侧模拟器出现棋盘就能玩（鼠标拖车）
7. 改了 `src/` 之后要重新执行 `node tools/build.mjs`，`dist/` 才会更新

抖音开发者工具**等确认个人资格后再装**（官方口径称个人仅支持「小玩法」，可能白装）。

## 为什么关卡是离线预生成的

关卡由 BFS 验解保证有解，但求解在运行时要几百毫秒/关，玩家点「开始」会卡。
所以离线跑一次产出 `src/data/levels.js`（纯数据），运行时秒开；表用完后现生成兜底（`R.getLevel()`）。

**步数语义（重要）**：一辆车一次拖「任意格」= 1 步。早期 BFS 每次只走 1 格、
把「格数」当步数（比如真实 2 步的局记 5），导致星级判定与难度曲线全失真 —— 已修，
冒烟测试里有专门断言守住这个语义。

**难度曲线（v2 生成器）**：1~2 关为手工教学关（2 步），第 3 关起按曲线 2 → 10 步
分段递增（每 20 关平均：2.9 / 4.1 / 5.3 / 6.0 / 6.8 / 7.3 / 8.0 / 8.8 / 9.1 / 10.0，
实测零偏差，抽样复核通过）。v1 的曲线在第 20 关就封顶，后 180 关一个难度 —— 已废弃。

生成器原理：随机撒 8~11 车的棋盘 → 每个完整求解一次入池 → 按曲线就近分配（分桶法，
不做无效重试）。分布依据：该撒法下 56% 无解、有解中 70% 落在 2~6 步、9~10 步约 5%。
重生成：`node tools/genlevels.mjs 200 8`（8 进程并行约 6 分钟）。

## 三端发布流程

**Web / 网页游戏平台（最快见钱）**

1. `node tools/build.mjs`，取 `dist/web/`
2. 上传 CrazyGames（开放提交、审核 1~2 天、无独占要求）
3. Poki 是精选制且要求网页独占，放到最后再谈

**微信小游戏**

1. 微信公众平台注册小游戏（主体选「个人」，一级类目「游戏」，**名称一次定死，注册后不可改**）
2. **注册完立刻提备案**（5~20 个工作日，全流程瓶颈；免费、不需要服务器和域名）
3. 微信开发者工具打开 `dist/wx/`（`project.config.json` 里的 appid 换自己的）
4. 累计独立访客 UV > 500 后开通流量主，回填 `src/config.js` 的广告位 ID

**抖音小游戏**

1. 抖音开发者工具打开 `dist/tt/`
2. 资格口径有冲突（官方 FAQ 称个人仅支持「小玩法」），**以注册实测为准**

## 广告位设计

| 位置 | 类型 | 说明 |
|---|---|---|
| 提示（看广告给一步最优走法） | 激励视频 | 主动触发，玩家想要才点 |
| 每过 3 关 | 插屏 | 自然停顿点，不打断操作 |

未填广告位 ID 时走空跑放行（见 `adapter/minigame.js`），开发期不受阻。
